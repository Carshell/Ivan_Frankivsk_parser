# Довідник об'єктів для блоку безпеки (п.5 ТЗ)

`security_objects.json` — ведеться і поповнюється **вручну**. Свідомо не заповнений
"з коробки": координати чутливих об'єктів (військові, енергетика тощо) не
вигадуються і не досліджуються автоматично — тільки те, що людина сама перевірила
і додала.

## Формат

Список об'єктів, кожен:

```json
{"name": "Назва об'єкта", "type": "аеродром", "lat": 48.xxxx, "lon": 24.xxxx}
```

`type` — за категоріями з ТЗ: `аеродром`, `військовий об'єкт`, `ТЕЦ/підстанція`,
`ж/д вузол`, `нафтобаза`, `промисловість`.

## Як знайти координати

Відкрий об'єкт на Google Maps → правий клік по точці → перше число у списку, що
з'явиться, це `lat, lon` (широта, довгота — саме в такому порядку).

## Поки файл порожній

`claude_prompt.txt` явно інструктує Claude: якщо `nearby_objects` порожній —
оцінювати `risk_level` консервативно (не нижче "Середній") лише на основі
наявності укриття в оголошенні, і прямо писати в reasoning, що довідник ще не
заповнений. Це чесніше, ніж вигадувати відстані до неіснуючих даних.

`security_objects.json` в `.gitignore` — не комітиться (може містити чутливі
локації). У репозиторії лежить лише `security_objects.example.json` як шаблон.
